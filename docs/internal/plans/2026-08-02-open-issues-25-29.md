**Project meaning:** A successful-looking deferred save must not be followed by a stop/restart that silently destroys the edit round.

**Technical contract:**
- Track pending-shutdown files/count from successful `session.save` responses.
- Clear/update the tracked state only from authoritative subsequent save/flush/session transitions; do not infer durability from `dirty:false`.
- Surface pending state through `xedit_dirty`.
- Refuse normal stop/restart while pending saves exist. `force:true` remains explicit abandonment and must report the risk.
- Correct `skills/xedit-automation/SKILL.md` and the affected core KB records so restart is no longer prescribed as durability proof.
- Rebuild root `dist` and the materialized plugin tree.

**Dependencies:** None. This is the first implementation batch because current guidance points into a known data-loss path.

**Semantic acceptance:** Stateful unit fixtures reproduce save response `savedNowCount:0` plus pending count, `dirty:false`, and lifecycle refusal. Normal no-pending lifecycle behavior remains unchanged. No live stop/restart is performed without separate permission.

**Recovery checkpoint:** Preserve request/response fixtures and list every corrected guidance record. The remaining upstream capability is represented by the authorized TES5Edit issue.
